# 디자인 방향

## 문제

기존 화면은 어두운 배경, 네온 계열 강조색, 큰 둥근 카드, 과한 "AI" 표현 때문에 실제 관제 도구보다 데모용 AI 제품처럼 보였다. 문구도 사용자가 할 일을 바로 알려주기보다 홍보 문장처럼 읽혔다.

## 변경 방향

- 어두운 네온 대시보드에서 밝은 운영 도구 화면으로 전환
- 큰 둥근 카드, 글로우, 그라디언트 제거
- IBM Carbon에 가까운 중립 팔레트 사용: 흰색, 회색, 검정, 파란색 하나
- 텍스트는 기능 중심으로 축소
- "AI 이벤트" 대신 "감지 후보" 사용
- "확정"보다 "검토"를 전면에 둠
- 영상 저장, 자동 판정 같은 오해를 줄이는 문구 유지

## 새 톤

- 제품 홍보보다 관제 업무 화면
- 감성적 문구보다 상태, 후보, 검토 중심
- AI가 주인공이 아니라 운영자가 주인공

## UI 원칙

- 표면은 평평하게, 구분은 선과 배경색으로 처리
- 상태 색상은 의미가 있을 때만 사용
- CTA는 하나만 강하게 표시: 데이터 갱신
- 이벤트 카드는 심각도 색상 막대만 사용
- 문장은 짧게 쓴다
- CCTV 선택은 목록과 지도 모두 같은 작업 영역(영상+연결 후보)을 선택하게 한다
- 이벤트 상세를 선택하면 지도와 영상도 해당 지점으로 이동한다. 후보가 없는 지점에는 다른 CCTV의 이벤트를 남기지 않는다
- 지도는 전체 지점과 오탐을 제외한 후보 건수/긴급도를 표시하고, 영상 연결 상태 점과 선택 테두리를 별도로 구분한다
- 개략도의 밀집 지점 라벨은 클릭 영역이 겹치지 않도록 보정한다. 실제 도로 지도나 다수 지점 클러스터링을 대신하지 않는다
- 검색/큐 정렬은 목록만 좁히고 현재 보고 있는 CCTV 상세를 다른 지점으로 바꾸지 않는다
- 현재 영상은 후보 감지 시각의 녹화 영상이 아님을 명시한다
- 실제 연결 전 소스 권한, 저장 제한, 재배포 제한을 UI에서 항상 보이게 한다
- 이벤트 검토는 일회성 버튼이 아니라 최근 처리 이력으로 남겨 운영 흐름을 보여준다
- 확인/오탐 처리에는 짧은 처리 사유를 남겨 나중에 오탐 패턴과 운영 판단을 되짚을 수 있게 한다
- 이벤트 상세 화면은 감지 근거와 검토 타임라인을 함께 보여줘 운영자가 왜 처리했는지 빠르게 복기하게 한다
- 감지 후보 목록은 전체/검토/긴급/확인/오탐 큐로 나눠 운영자가 당장 볼 항목을 줄일 수 있게 한다
- 후보가 늘어날 것을 전제로 지점명, 이벤트명, 근거 문장 검색을 제공해 긴 목록에서 바로 좁힐 수 있게 한다
- 후보 정렬은 긴급도, 신뢰도, 최신순, 지점순을 제공해 상황실의 관점 전환을 빠르게 한다
- 처리 사유는 상태별로 분리해 확인 사유와 오탐 사유가 섞이지 않게 한다
- 검토 이력은 브라우저 저장소에만 두되 JSON/CSV로 내려받을 수 있어 수동 리포트와 QA에 활용할 수 있게 한다
