# 관제 화면 분리

## 화면 계약

- `/`: 전체 CCTV. 목록·도로 지도·선택 영상·후보 검토를 연동한다.
- `/events`: 후보 감지 지점. `needs_review`와 `confirmed` 후보가 하나 이상 연결된 지점만 목록·지도·영상 선택에 포함한다. `dismissed`는 제외한다. 중복 후보가 있어도 지점을 중복 표시하지 않는다.
- `/monitor`: 내 모니터. 선택한 CCTV를 최대 4대의 TV처럼 배치한다. 브라우저 저장소에는 선택한 CCTV의 이름·노선·CCTV 좌표·안정적인 선택 키만 보관한다. 사용자 GPS, 인증키, 영상 URL은 보관하지 않는다.

## 의미와 제한

- 감지 후보는 사고 확정이 아니다. `confirmed`는 운영자가 확인한 후보이며, 실제 현장 상황의 지속 여부를 보장하지 않는다.
- 실제 ITS 메타데이터 연동과 자동 영상 감지는 별개다. 실제 소스에는 아직 자동 감지기가 연결되지 않았으므로 후보가 없는 것이 정상 교통의 근거가 아니다.
- 후보 전용 화면의 마지막 지점이 오탐 처리되면 해당 지점이 사라져야 한다. 다른 일반 CCTV의 영상을 대신 보여주지 않는다.
- 내 모니터는 같은 브라우저·같은 origin에서 복원된다. 다른 기기 동기화, 서버 계정 저장, 녹화 기능이 아니다. 브라우저 데이터를 지우면 선택도 삭제된다.
- 재방문은 선택 목록만 복원한다. 사용자가 영상 정보를 갱신하고 각 영상을 명시적으로 연결한다. 자동 영상 재생·자동 정기 조회는 하지 않는다.
- ITS 응답 ID는 조회 구역에 따라 바뀔 수 있으므로 모니터 복원은 이름·CCTV 좌표로 지점을 식별한다. 저장된 ID나 이전 영상 URL을 그대로 신뢰하지 않는다.

## 수용 검사

- 전체 화면의 후보 없는 지점은 후보 전용 화면에서 제외된다.
- 오탐 처리는 지도 배지·지점 목록·영상·후보 큐·집계에 일관되게 반영된다.
- 후보가 없는 실제 소스 화면에 샘플 감지를 넣지 않는다.
- 모니터 추가·중복 방지·최대 대수·순서 변경·제거·새로고침·재방문 복원을 검사한다.
- localStorage의 잘못된 JSON·알 수 없는 버전·잘못된 좌표·용량/권한 오류를 안전하게 처리한다.
- 모니터 삭제나 화면 이탈 이후 늦은 영상 정보 응답이 삭제된 선택을 복원하지 않는다.
- 저장소에 영상 URL, 인증키, GPS가 없는지 검사한다.
- 실제 도로 지도는 OSM 출처를 표시하고, 자동 QA는 타일을 차단/fixture 처리한다. 대량 타일 조회나 영상 프레임 캡처는 하지 않는다.
- 320px·390px·데스크톱에서 화면 넘침과 주요 버튼 조작을 확인한다.

이 문서는 구현·QA 계약이며, 각 검사의 실제 결과는 통합 QA 기록에서 별도로 남긴다.
