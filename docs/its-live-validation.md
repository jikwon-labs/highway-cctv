# ITS 실제 정보 조회 검증

검증일: 2026-10-18 (KST). 사용자 승인 범위에서 로컬 metadata 조회만 수행했습니다.

## 실제 확인 결과

- 공식 `cctvInfo` API, `type=ex`, `cctvType=4`, JSON
- 조회 범위: 경도 127.1~127.12, 위도 37.32~37.35
- HTTP 200, CCTV 2개, 영상 URL이 있는 항목 2개
- 실제 `coordx`, `coordy`, `cctvtype`은 숫자형으로 수신됨
- 앱 `/api/cctv`에서도 `source=its`, 피드 2개, 후보 0개 및 유효한 좌표 확인
- 반복 갱신의 `generatedAt`이 같아 동일 프로세스 캐시 사용 확인
- 브라우저 목록·지도 선택 및 명시적 영상 연결 전 대기 화면 확인
- 영상 주소만 받은 항목은 `재생 미확인`, 지연은 `미측정`으로 표시
- 영상 재생 요청, 프레임 추출, AI 모델 호출, 녹화·재배포는 수행하지 않음

## 보완 사항

1. 숫자형 필드 변환 오류를 재현한 뒤 string/number 양쪽을 지원하도록 수정했습니다.
2. API route가 매번 새 adapter를 만들어 캐시가 무효화되던 문제를 수정했습니다. 동일 프로세스의 설정별 인스턴스를 재사용하고 동시 조회는 하나로 합칩니다.
3. 기본 구역을 소규모로 축소하고 upstream timeout/redirect 차단 및 예외 메시지 비노출을 적용했습니다.
4. HTTP 200이라도 provider 오류 코드나 잘못된 응답은 성공한 빈 목록으로 감추지 않습니다.
5. 실제 모드의 초기 샘플 CCTV/가상 후보를 제거했습니다. request-time 설정만 읽고 API는 `데이터 갱신`으로 조회합니다.
6. `영상 연결 시작` 전에는 video/HLS를 만들지 않습니다. 지점 또는 URL 변경 시 재생 동의를 다시 받고, 중지 시 HLS/미디어 연결을 정리합니다.
7. 실제 분석 결과가 아닌 장식용 박스를 제거했습니다.

- 클라이언트 정적 파일 23개에서 실제 인증키 일치 0건
- staged diff, HTML, API JSON에 실제 ITS 인증키가 포함되지 않았음을 값 비노출 방식으로 확인
- `.env.local`은 Git ignore 상태이며 로컬 권한은 0600으로 설정

## 로컬 실행

현재 로컬 `.env.local`의 모드는 `its`입니다. 인증키는 파일에만 보관하며 이 문서나 커밋에 포함하지 않습니다. `.env.example`은 여전히 안전한 `mock` 기본값입니다.

```bash
cd ~/Documents/highway-cctv
pnpm dev --hostname 127.0.0.1
```

1. 화면 상단의 `ITS 실제 소스 · 조회 전`을 확인합니다.
2. `데이터 갱신`으로 소구역 목록을 조회합니다.
3. 지도나 목록에서 지점을 선택합니다.
4. 실제 영상 재생은 해당 이용조건을 확인한 뒤 `영상 연결 시작`을 눌러 수행합니다.

## 남은 확인

- 실제 HLS 영상 재생, URL 만료, CORS 및 연속 재생 품질은 아직 검증하지 않았습니다.
- 공개 서비스, 영상 저장/재배포, AI 프레임 추출의 허용 범위는 인증키 발급과 별개로 확인해야 합니다.
- 캐시는 process-local이며 다중 서버/서버리스 전체의 호출 한도를 보장하지 않습니다. 외부 배포 전에 공유 캐시·접근 제어·rate limit이 필요합니다.
- 교통소통/돌발상황 API는 아직 연결하지 않았습니다.
