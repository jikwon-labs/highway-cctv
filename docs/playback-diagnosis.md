# CCTV 재생 끊김 진단

## 재현

로컬 production build, Chromium 145에서 같은 영상 연결 오류를 재현했습니다. API 키·영상 URL·영상 프레임은 이 기록에 포함하지 않았습니다.

- 브라우저 `canPlayType(application/vnd.apple.mpegurl)` 결과: `maybe`
- 기존 구현은 이 값이 비어 있지 않으면 native HLS를 우선 선택
- native 경로에서 `MediaError.code=4`, `DEMUXER_ERROR_COULD_NOT_PARSE` 관찰
- 이때 UI는 모든 native 오류를 URL 만료/접근 제한 문구로 표시했음

이는 관찰한 브라우저 경로의 원인입니다. 사용자의 모든 브라우저/모든 CCTV 장애가 같은 원인이라는 뜻은 아닙니다.

## 변경

- MSE가 지원되면 HLS.js를 우선 사용하고, MSE가 없을 때 native HLS를 사용
- 미디어 형식 해석/디코딩 오류와 네트워크/HTTP 접근 오류를 분리
- 원본 예외·URL을 표시하지 않는 정적 오류 문구 사용
- 사용자가 명시적으로 재시도할 수 있는 `다시 연결` 추가
- 중지는 기존대로 HLS 인스턴스를 파기하고 video source를 제거

## 실제 재검증

동일 구역의 실제 스트림을 녹화·캡처 없이 재생 상태 값만 관찰했습니다.

- 10초: HLS.js, 재생 시각 10초, readyState 4, 오류 없음
- 20초: 재생 시각 20초, 재생 유지, 오류 없음
- 35초: 재생 시각 35초, 재생 유지, 오류 없음
- 연결 중지 후 video 요소 제거 확인

## 제한

- 35초 검증은 장시간 무중단 또는 모든 공급 영상의 정상 동작을 보장하지 않습니다.
- upstream URL 만료, HTTP 401/403/404/410, CORS, 일시적 세그먼트 장애는 여전히 발생할 수 있습니다.
- 접근 제한을 프록시나 헤더 위조로 우회하지 않습니다. 필요하면 데이터 갱신 또는 다른 지점을 선택합니다.
- 이번 검증은 영상 저장·재배포·AI 분석을 수행하지 않았습니다.
