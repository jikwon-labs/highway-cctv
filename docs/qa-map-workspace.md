## 브라우저 검증

검사 결과 원본: [checks.json](qa/phase3/checks.json). 같은 이름의 재검사는 최종 결과로 집계했으며, 최종 26개 검사 모두 통과했습니다.

- 지도 배지: CCTV 상태 점 / 후보 건수 / 최고 긴급도 / 선택 테두리 구분
- 용인 지도 지점 선택 → 용인 CCTV와 정체 후보 동시 선택
- 역주행 후보 상세 선택 → 판교 CCTV와 지도 선택 동시 변경
- 하남(후보 없음) 선택 → 이전 후보 상세 해제
- 확인된 후보가 검토 큐에 없어도 지점에서 해당 후보 상세 확인 가능
- 빈 검색 결과가 현재 영상/상세를 다른 지점으로 변경하지 않음
- 영상 하단의 지점별 후보 카드로 상세 선택 가능
- CCTV 상태 필터 변경 시 영상과 연결 이벤트 일치
- 필터 밖 CCTV의 이벤트를 선택하면 해당 지점을 보이도록 CCTV 필터 해제
- 데이터 갱신 후 선택한 지점/후보 유지
- 실제 `/api/cctv` 응답을 지연시키고 대기 중 용인/하남으로 이동한 뒤, 응답 완료 후에도 최신 지점/후보(또는 명시적 후보 없음)를 유지
- 오탐 처리 시 지도 배지가 즉시 감소
- Enter 키로 지도 선택 동작 확인
- 320/390/1440px에서 마커 사각형 겹침 및 페이지 가로 넘침 없음
- 지도 버튼 높이 44px 및 중심 좌표 클릭이 해당 마커에 도달하는지 확인
- 런타임 error/unhandledrejection 수집에서 오류 없음

## 발견하고 수정한 문제

- 기존에는 CCTV를 바꿔도 다른 지점 후보가 상세에 남을 수 있었음 → 지점·후보 동시 선택, 연결 지점 일치 검사로 수정
- 후보가 없는 지점에서 큐의 첫 후보로 대체됨 → 빈 상세로 처리
- 독립 코드 리뷰에서 갱신 대기 중 최신 선택이 이전 지점으로 되돌아가는 회귀 발견 → 단일 workspace state와 functional 보정으로 수정, 실제 지연 응답으로 실패/성공 재검증
- 밀집된 판교/터널 라벨과 작은 화면의 인접 마커가 겹침 → 개략도 라벨 배치 보정, 360px 지도 높이, 정보 영역을 지도 아래로 분리
- 브라우저 자동화의 Enter keyDown만으로 활성화되지 않는 사례는 rawKeyDown/char/keyUp으로 실제 키 입력을 전달해 재검증 (앱에 불필요한 키보드 핸들러를 추가하지 않음)

## 남은 제한

- 개략도는 소수 지점 MVP용입니다. 라벨을 피해서 배치하므로 정확한 도로 위치 표시나 길 안내용 지도가 아닙니다. 다수/동일 좌표 CCTV에는 실제 지도 SDK와 클러스터링이 필요합니다.
- 실제 HLS 재생/URL 만료/CORS는 API 키와 이용조건 확보 후 별도 검증이 필요합니다.
- 영상은 후보 감지 시각의 녹화 영상이 아니며 화면에도 이 점을 명시했습니다.
- 검토 이력은 기존처럼 브라우저에 보관합니다. 다중 운영자 동기화와 서버 감사로그는 이번 범위가 아닙니다.
